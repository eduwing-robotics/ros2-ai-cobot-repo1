# 불량대책서 필드 매핑

`불량대책서_표준양식_v2.xlsx`의 토큰은
[generate_defect_reports.py](../generate_defect_reports.py)가 치환한다. 별도 품질
스키마나 원인 추정 데이터는 사용하지 않는다.

## 발행 단위와 시점

Sequencer가 FAIL 검사를 확정할 때 `production.unit_defects`와
`production.defect_report_deliveries`를 같은 트랜잭션에 기록한다. MainServer 생성기의
기본 `local` 모드는 확정 불량을 조회해 다음 XLSX 파일을 생성하며, 발송 대기 행을
선점하거나 SENT로 변경하지 않는다. 명시적인 `email` 모드에서만 발송 대기 행을
선점하고 XLSX 첨부 메일을 전송한다.

```text
QA-D{unit_defect_id}-{part_id}-{defect_type}.xlsx
```

따라서 불량이 한 건만 확정되어도 Job 완료를 기다리지 않고 대책서 한 건이 발행된다.
메인 대책서는 해당 확정 불량 1건의 사실·조치·효과 확인을 A4 한 장에 기록한다.
누적 수량·PPM·슬롯별 분포는 기본 양식에 표시하지 않는다. 발생 슬롯은 해당 불량의
위치 식별을 위해 유지한다.
기존 파일은 담당자 회신 보존을 위해 덮어쓰지 않는다.
Migration은 기존 불량을 대기열에 소급 등록하지 않아 활성화 시 과거 메일이 일괄 발송되지
않는다.

## 데이터 소스와 연결 규칙

| 구역 | 소스 |
|---|---|
| Job 식별자 | `production.jobs` |
| Unit, 판정, 검사 시각·이미지 경로 | `production.units` |
| 불량 ID·유형 | `production.unit_defects` |
| Slot과 Part 연결 | `production.product_slots` |
| Part ID·이름·범주 | `production.parts` |
| 전송 상태·재시도 | `production.defect_report_deliveries` |
| 현재 부품과 대체품 후보의 MPN·사양·공급사·가격 | 데이터시트 `Components` |

## 양식 범위

| 구역 | 입력 범위 |
|---|---|
| 발생 정보 | 문서번호, Job·Unit·Slot·불량 ID, 검사·발행 시각, 부품, 불량 유형을 자동 입력. 담당자·회신 기한·실제 납품업체와 Lot/PO는 담당자 작성 |
| 불량 현상 및 판정 근거 | 해당 Unit·슬롯의 불량 유형, 이미지와 이미지 상태를 자동 입력. 판정 기준·관찰 결과·근거 기록번호는 담당자 작성 |
| 조치·효과 확인·종결 | 초동조치, 발생·유출 원인, 재발방지, 효과 확인, 확인자·종결일·종결 판정을 담당자 작성 |

`대책서`와 `대체품` 두 시트로 구성한다. 메인 `대책서`의 인쇄 범위는 `A1:L36`,
A4 세로 한 페이지 맞춤이며, `대체품`은 `A1:F13`, A4 가로 한 페이지 맞춤이다.
진남색·진회색 띠는 구획 제목, 노란 칸은 담당자 입력 영역이다. 문서 상태는
발행·진행중·검증중·종결 중 선택하며 실제 조치·검증 결과를 확인한 뒤 담당자가 갱신한다.
효과 확인은 방법·기간·기준·결과·확인자를 기록하는 서술형 칸이다. 필요한 검사 수량은
본문에 적고, 원인 입증에 필요한 상세 통계는 별도 근거 기록번호로 연결한다.
누적 통계표는 포함하지 않는다. `대체품` 시트에는 현재 부품과 같은 범주의 나머지
후보에 대해 MPN·핵심 정격·공급사·단가·가격 기준 수량·가격 확인일 및 자료 출처를
자동 입력한다. 현재 부품은 DB의 부품 범주와 이름을 데이터시트의 범주·MPN과 대조한다.
후보 목록은 호환성이나 불량 개선 효과를 보증하는 추천 순위가 아니며, 적합성 검증과
변경 승인 후 적용한다. 메인 대책서에는 후보 목록과 가격을 표시하지 않는다.

DB에 없는 주차별 추세, 레시피 변경 이력, 과거 대책서와 자동 원인 추정은 양식에 넣지
않는다. 원인·조치·효과는 생성된 XLSX에 담당자가 작성하며 DB로 역기록하지 않는다.

## 검사 이미지

`inspection_image_path`는 `DEFECT_IMAGE_ROOT` 아래의 상대경로만 허용한다. JPEG·PNG만
포함하며 `DEFECT_IMAGE_MAX_BYTES`를 넘거나, 절대경로·상위경로 이탈·파일 없음·형식
불일치이면 문서에 상태만 기록하고 발행은 계속한다. 이미지 경로와 포함한 이미지의 SHA-256은
`A19` 셀의 메모에 기록한다. 이미지 상태는 같은 셀 본문에 표시한다.

## 파일과 전송 무결성

템플릿 치환 후 남은 토큰과 XLSX ZIP 무결성을 확인한 다음 원자적으로 파일을 확정한다.
새 보고서 디렉터리와 파일은 각각 소유자 전용 `0700`, `0600`으로 생성한다.
메일 실패 시 같은 파일과 결정적 `Message-ID`로 재시도하며, 성공한
`unit_defect_id`는 다시 선점하지 않는다. SMTP는 SSL 또는 STARTTLS만 허용하고 수신자
도메인 allowlist와 권한이 제한된 비밀파일을 사용한다.
