# 불량대책서 필드 매핑

`불량대책서_표준양식.xlsx`의 토큰은
[generate_defect_reports.py](../generate_defect_reports.py)가 치환한다. 보고서 데이터는
`production` 6개 테이블과 부품 데이터시트 XLSX만 사용하며, 별도 품질 스키마에는
저장하지 않는다.

## 발행 단위

완료된 Job의 FAIL Unit을 `job_id + part_id + defect_type`으로 묶는다.

```text
QA-J{job_id}-{part_id}-{defect_type}.xlsx
```

기존 파일은 덮어쓰지 않는다. 담당자가 보고서에 입력한 원인·대책·결과를 보존하기
위한 규칙이다.

## 데이터 소스

| 구역 | 소스 |
|---|---|
| Job와 기간 | `production.jobs` |
| Unit, 판정, 검사 시각·이미지 | `production.units` |
| 불량 유형 | `production.unit_defects` |
| Slot | `production.product_slots` |
| Part 이름·범주 | `production.parts` |
| Group, 제조사, 모델, 사양, 대체 후보 | 데이터시트 `HBM Package Board BOM`·`Components` |
| 검사와 이상 조치 | 데이터시트 `Checklist` |
| 출처와 확인일 | 데이터시트 `Sources` |

## 주요 토큰

| 토큰 | 값 |
|---|---|
| `{{alert_code}}` | `QA-J{job_id}-{part_id}-{defect_type}` |
| `{{issued_at}}` | 파일 생성 시각 |
| `{{part_id}}`, `{{part_name}}` | Production Part |
| `{{defect_type}}` | 확정 불량 유형 |
| `{{period_start}}`, `{{period_end}}` | Job 시작·종료 시각 |
| `{{inspected_quantity}}` | 검사 Unit 수 × 해당 Part의 Slot 수 |
| `{{defective_quantity}}` | 그룹에 포함된 불량 레코드 수 |
| `{{defect_ppm}}` | 불량 수량 / 검사 수량 × 1,000,000 |
| `{{unit_impact}}` | 검사 Unit 중 영향 Unit 수 |
| `{{hotspot}}` | Slot별 발생 건수 |
| `{{unit_id}}`, `{{slot_code}}` | 확정 근거 목록 |
| `{{group_id}}`, `{{manufacturer}}` | 데이터시트 부품 정보 |
| `{{incoming_inspection}}` | 공통·해당 범주의 입고 검사 |
| `{{assembly_control}}` | 조립·보관 관리 |
| `{{reliability_test}}` | 기능·신뢰성 검사 |
| `{{action_on_anomaly}}` | 이상 시 조치 |

데이터시트에 Part가 없으면 카탈로그 토큰은 `데이터시트 연결 없음` 또는 `—`로
표시하고 보고서는 계속 생성한다. 템플릿에 남은 미해결 토큰도 `—`로 치환하며,
생성된 XLSX의 ZIP 무결성과 잔여 토큰을 확인한 뒤 원자적으로 파일을 이동한다.

## 담당자 입력

`assignee`, 지원 팀, 기한, 원인, 조치와 효과 확인 항목은 생성 시
`배정 대기` 또는 `담당자 입력`으로 표시한다. 회신은 생성된 XLSX 파일에 직접
작성하며 DB로 역기록하지 않는다.
