# 불량대책서 필드 매핑

`불량대책서_표준양식.xlsx`의 토큰은
[generate_defect_reports.py](../generate_defect_reports.py)가 치환한다. 별도 품질
스키마나 원인 추정 데이터는 사용하지 않는다.

## 발행 단위와 시점

Sequencer가 FAIL 검사를 확정할 때 `production.unit_defects` 한 행과
`production.defect_report_deliveries` 한 행을 같은 트랜잭션에 기록한다. MainServer
worker는 대기 행을 선점해 다음 파일을 만들고 XLSX 첨부 메일로 전송한다.

```text
QA-D{unit_defect_id}-{part_id}-{defect_type}.xlsx
```

따라서 불량이 한 건만 확정되어도 Job 완료를 기다리지 않고 대책서 한 건이 발행된다.
동일 Job·부품·유형의 수량과 슬롯 분포는 해당 불량의 검사 시각까지 누적한 값이다.
기존 파일은 담당자 회신 보존을 위해 덮어쓰지 않는다.
Migration은 기존 불량을 대기열에 소급 등록하지 않아 활성화 시 과거 메일이 일괄 발송되지
않는다.

## 데이터 소스와 연결 규칙

| 구역 | 소스 |
|---|---|
| Job, 기간, 레시피 버전 | `production.jobs` |
| Unit, 판정, 검사 시각·이미지 경로 | `production.units` |
| 불량 ID·유형 | `production.unit_defects` |
| Slot과 Part 연결 | `production.product_slots` |
| Part ID·이름·범주 | `production.parts` |
| 전송 상태·재시도 | `production.defect_report_deliveries` |
| MPN·사양·공급사·가격 | 데이터시트 `Components` |
| 검사와 이상 조치 | 데이터시트 `Checklist` |

`parts.part_category`와 데이터시트 `Components.Part Type`을 먼저 맞추고,
`parts.part_name`과 `Components.Manufacturer Part Number`를 정확히 비교해 현재 부품을
선택한다. 즉, `parts`에는 생산 식별·재고 정보만 있고 사양·공급사·가격은 데이터시트에서
가져온다. 일치 행이 없으면 `불일치 — 담당자 확인 필요`로 표시하고 문서 발행은 계속한다.

## 양식 범위

| 시트 | 자동 입력 범위 |
|---|---|
| 대책서 | 문서번호, Job·Unit·Slot, 검사 시각, 부품, 불량 유형, 누적 수량·PPM·발생 위치 |
| 검증 | 담당자가 대책 적용 후 직접 작성하는 효과 검증·종결 영역 |
| 근거 | 확정 불량 목록, 이미지 경로·상태·SHA-256, 해당 검사 이미지 |
| 판단자료 | 데이터시트 `Checklist`의 품질 기준과 원본 식별 정보 |
| 대체품 | DB 현재 부품과 데이터시트 매칭 결과, 같은 범주의 나머지 후보 |

DB에 없는 주차별 추세, 레시피 변경 이력, 과거 대책서와 자동 원인 추정은 양식에 넣지
않는다. 원인·조치·효과는 생성된 XLSX에 담당자가 작성하며 DB로 역기록하지 않는다.

## 검사 이미지

`inspection_image_path`는 `DEFECT_IMAGE_ROOT` 아래의 상대경로만 허용한다. JPEG·PNG만
포함하며 `DEFECT_IMAGE_MAX_BYTES`를 넘거나, 절대경로·상위경로 이탈·파일 없음·형식
불일치이면 문서에 상태만 기록하고 발행은 계속한다. 포함한 이미지의 SHA-256을 함께
기록한다.

## 파일과 전송 무결성

템플릿 치환 후 남은 토큰과 XLSX ZIP 무결성을 확인한 다음 원자적으로 파일을 확정한다.
새 보고서 디렉터리와 파일은 각각 소유자 전용 `0700`, `0600`으로 생성한다.
메일 실패 시 같은 파일과 결정적 `Message-ID`로 재시도하며, 성공한
`unit_defect_id`는 다시 선점하지 않는다. SMTP는 SSL 또는 STARTTLS만 허용하고 수신자
도메인 allowlist와 권한이 제한된 비밀파일을 사용한다.
