# 연속 이동 기능 조회 지연 수정 — 2026-09-13

실행 ad2fb3e0-c317-45e0-8dd6-f3def01e80f8은 GPU-01/HBM-01 배치 동작 후 HBM-02 픽업과 제거 검사를 통과했으나, 기판 이동 전 continuous driver capability timeout으로 정지했다. 직접 실패 조건은 /fr_command_server/get_parameters의 continuous_movej_revision 응답이 2초 안에 완료되지 않은 것이다. 응답 지연의 DDS/드라이버 내부 발생 지점까지 추적한 것은 아니다.

## 변경

로컬 피드백을 FR5FB002(v2)로 확장하여 컴파일된 드라이버의 per-command blending 지원 비트를 매 프레임 전송한다. API는 최신 프레임과 지원 비트를 확인하여 연속 이동을 허용한다. 이 PC의 조립 도중 기능 조회 DDS 요청은 제거된다. 위치, 정지, 오류, 모드, 프레임 검사와 250ms 신선도 제한은 유지한다.

구버전 프로토콜, 지원 비트 없음, 오래된 프레임, 다른 드라이버 인스턴스, 거부된 패킷은 기능 검증에 사용할 수 없다. 드라이버 교체 시 API도 재시작해야 한다. 로컬 통신 미사용 구성은 기존 파라미터 검증을 유지하되 일반 서비스 제한 시간(기본 10초)을 사용하고 만료된 future를 취소한다. 이 PC에서는 해당 DDS 경로를 사용하지 않는다.

## 함께 점검한 통신 경로

- 준비/계획 확인: 기존 읽기 상태 재조회와 계획 확인 절차 유지. 지연 응답 회귀 검사 포함.
- 로봇 상태: 로컬 수신 스레드로 ROS 콜백 지연과 분리. 250ms 제한 유지.
- 연속 이동 기능: 최신 로컬 프레임으로 확인하여 부품마다 발생하던 DDS 왕복 제거.
- 이동/그리퍼 명령: 기존 제한 시간 유지. 실행 여부가 불명확한 명령을 자동 재전송하지 않음.
- 연속 이동 큐: 일부 명령 접수 후 실패하면 정지/복구 요구. 자동 재생하지 않음.
- 작업 결과/일시정지 확인: 결과 불명확 시 다음 작업 진입 차단 유지.

## 검증 및 적용

관련 테스트 28개, 전체 테스트 984개 통과(42.56초). Python 197개와 셸 구문 검사 통과. C++ 드라이버/API 빌드 완료. 테스트 환경이 운영 소켓 이름을 상속하던 문제도 격리했다.

로봇 정지(robot_motion_done=1), active_operation=null, recovery_required=true를 확인한 뒤 드라이버/API를 재시작했다. 카메라 서비스는 계속 실행된다. 복구/조립/그리퍼 명령을 전송하지 않았다. 재시작 전 held_candidate는 HBM-02였으며 재시작 후 메모리 값이 비어도 실제 그리퍼가 비었다는 뜻은 아니다.

실제 조회 결과는 runtime/capability_fix_20260913/validation.json에 저장한다. 물리 조립 전체 사이클 검증은 아직 수행하지 않았다. 본 수정은 확인된 기능 조회 시간 초과 경로를 제거하며, 모든 하드웨어·네트워크 오류가 발생하지 않는다는 보장은 아니다. 드라이버 발행 시각 검증은 SDK 내부 원본 패킷 신선도 검증을 대신하지 않는다.
