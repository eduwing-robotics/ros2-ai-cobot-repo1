# 두 세트 트레이 조립 지원 — 2026-09-11

## 원인

실행 5e4385d5-856c-480e-9cbd-aa8b07dbd0d9는 TrayHome 이동을 완료한 뒤 capture_tray에서 GPU 초과 검출 오류로 종료됐다. 검출기는 기존 레이아웃에 따라 두 세트 50개를 발행했지만 촬영 수집기는 한 세트 25개만 허용했다. VRM 정밀 보정과 파지 후 재고 검사에도 같은 전체 수량 가정이 남아 있었다.

## 동작

현재 기존 두 세트 배치를 유지한 채 한 기판분 25개를 선택한다. GPU·HBM·PM은 왼쪽, VRM·IND·SMD는 위쪽인 기존 1번 세트다. 나머지 세트는 비어 있거나 채워져 있어도 된다. 2번 세트 자동 전환이나 두 기판 연속 실행은 추가하지 않았다.

고정된 트레이 기준 좌표 영역으로 먼저 세트를 구분한다. 분리 경계는 기존 번호 순서 및 실제 50개 검출의 빈 간격을 확인해 설정 파일에 고정했다. 일부 검출이 빠졌다고 경계를 다시 계산하거나 다른 세트 부품으로 보충하지 않는다. 경계 12px 이내·영역 밖·선택 영역 초과 검출은 거부한다. 초기 선택 세트가 완전해진 다음 기존 물리 셀 추적과 품질 검사를 수행한다.

촬영 결과와 계획의 assembly_set_selection에 설정을 보존하고 VRM 보정 및 파지 후 검사에서 같은 영역을 사용한다. 원래 source ID와 좌표는 보존하며 계획의 조립 슬롯은 기존 25개다. 파지 대상이 아직 보이면 제거 성공으로 처리하지 않는다.

## 검출 지연 개선

현재 영상 검증 중 약 5초 된 결과 때문에 2초 최신성 기준에 걸리는 문제도 발견했다. 검출기의 40프레임 안정화 과정에서 변경되지 않은 클러스터 중앙값을 매 후보 비교마다 다시 계산하고 있었다. 같은 종류의 후보만 비교하고 중앙값을 해당 클러스터 변경 시 갱신하도록 수정했다.

실제 50개 자료·40프레임 비교에서 결과가 정확히 같았고 안정화 계산은 1.664초에서 0.078초로 줄었다. 이는 전체 검출 시간의 측정값은 아니다. 검출·API 서버 재시작 후 실제 최신 영상 검증은 3.212초 만에 25개 연속 품질 검사 및 스냅샷 변환을 완료했다. 관측한 영상 나이는 0.476~1.553초였다. 최신성·동작 안전 기준은 완화하지 않았다.

## 검증

- 최종 전체 회귀 테스트 849개 통과.
- 실제 두 세트 영상으로 VRM 정밀 보정 5개 완료(exit 0), 로봇 동작 없음. 증거 live_vrm.log.
- 실제 50개 자료에서 기존 1번 세트 25개의 좌표·source ID 유지.
- 다른 세트 비어 있음, 선택 세트 누락, 경계 모호함, 중복, GPU 파지 후 다른 GPU 잔존, 재고 좌표 변화 검사.
- 계획으로 선택 설정 보존 검사 및 안정화 좌표·종류·40프레임 지지 수 검사.
- 검출기와 API 재시작 완료. 실제 로봇 Start·이동·그리퍼·복구 명령은 보내지 않았다.
- 증거: runtime/two_set_fix_20260911/의 benchmark.json, tests_final.log, live_summary.json 및 진단용 snapshot.json. 진단 스냅샷은 이전 기판 기록을 참조하므로 실행에 사용하지 않는다.

기존 실패 실행의 복구 필요 상태를 유지한다. 현장 확인과 복구 후 새 실행 ID로 시작해야 한다. 실제 전체 물리 조립 완료는 이번 검증 범위가 아니다.
