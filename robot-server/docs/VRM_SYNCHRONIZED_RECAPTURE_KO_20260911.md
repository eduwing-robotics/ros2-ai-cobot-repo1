# VRM 정밀 보정 동기화 및 전체 재촬영

실행 `f126a3dd-94b0-4c54-9490-34b7e74dfb83`은 TrayHome 촬영 후 VRM-01 좌표 변화로 중단됐다. 최신 영상과 이전 검출 결과를 함께 사용하던 경로를 수정했다.

## 변경

- 영상·검출·카메라 내부 파라미터의 ROS 시각이 정확히 일치하는 자료만 사용한다.
- 서로 다른 12개 프레임으로 보정하며, 완료 시 다섯 부품 모두 현재 프레임 측정에 성공해야 한다.
- 품질을 통과한 좌표가 기존 좌표와 2mm 넘게 달라지면 정지 상태에서 선택된 25개 전체를 새로 촬영하고 VRM 보정을 처음부터 수행한다. 전체 재촬영은 최대 2회이며 전체 시간 제한을 유지한다.
- 물리 셀·트레이 등록 식별자 변경, 등록/변환 상실은 중단한다. 기존 기하·품질 기준은 완화하지 않았다.
- 새 vrm_refinement_window.py를 런처 필수 파일 검사에 포함한다.

## 검증 증거

`runtime/vrm_pipeline_fix_20260911/pipeline_report.json`과 `pipeline_final.log`:

- 실제 영상 촬영 → VRM 5개 보정 → 일반 부품 20개 계획 → 제어기 사전 검사 3회 통과(15.26/18.90/15.19초).
- 두 번째 진단 파일에만 3mm 오차를 주입해 전체 재촬영 1회 후 통과함을 확인했다.
- 회차별 IK 경유점 433개, 총 1299회 조회. 이동 명령 0개.
- 최초 진단의 ROS 콜백 오류는 lambda 래핑으로 수정했고 이후 위 3회가 통과했다. pipeline.log는 최초 실패 기록이며 최종 결과는 pipeline_final.log다.

최종 회귀 테스트 864개 통과(`tests_final.log`). 설치 검사와 `git diff --check` 통과.

## 적용 및 남은 현장 검증

런처와 보정 스크립트는 다음 실행의 새 프로세스가 소스 경로에서 읽는다. 이번 변경에 서버 재시작은 필요 없다.

마무리 시 API 조회 결과 기존 실행은 recovery_required, 완료 슬롯은 0개다. 실제 복구·Start·이동·그리퍼 명령은 보내지 않았다. 복구 CLI는 빈 그리퍼·빈 기판·트레이 부품·고정구의 작업자 현장 확인을 요구하므로 새 확인을 임의로 만들지 않았다. 현장 확인 후 복구 및 새 실행으로 전체 조립 검증이 남아 있다. 위 무동작 검증은 실제 전체 조립 성공을 의미하지 않는다.
