## 확인한 문제

실행 a5ebda23-7be4-4531-a0ff-df989c6e9fb0은 capture_tray에서 black_block:4 검출 신뢰도 중앙값 0.610/기준 0.700으로 네 차례 촬영 후 중단됐다. 이전 실행 326c23b2-f9d0-4ab8-8291-dfa80f238131은 black_block:5의 XYZ 변화 2.024mm(주로 깊이 1.992mm)로 중단됐다.

금요일의 전체 재촬영 처리는 VRM 정밀 보정 단계에만 연결돼 있었다. 앞선 트레이 촬영 단계는 좌표 변화 시 즉시 실패했다. 추가 해상도 검출도 PM/VRM/HBM/IND만 한 차례 수행했다.

## 변경

- GPU/HBM/PM/VRM/IND/CAP 모두 같은 프레임에서 640/960/1280 해상도와 180도 영상 회전 재검출을 사용한다. 품질 충족 시 추가 추론을 중단한다.
- 회전 마스크는 원래 crop 좌표로 역변환한 뒤 기존 중심 3px, 축 3도, 크기 0.8~1.2배, 깊이 2mm의 유일 대응 검사를 통과해야 채택한다. 낮은 신뢰도 값을 임의로 높이거나 새 물리 셀을 생성하지 않는다.
- capture_tray에서도 검증된 좌표 변화가 발생하면 전체 25개 캐시를 버리고 최대 2회 다시 측정한다. 기존 물리 셀 anchor·보정 해시와 전체 60초 예산은 유지한다. 셀 식별 모호성·등록 상실·보정 변경은 계속 거부한다.
- 픽업·배치·그리퍼·로봇 피드백 기준, 품질 임계값과 SMD 근접 정밀 측정 조건은 변경하지 않았다.
