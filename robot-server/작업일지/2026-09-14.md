## 6. 화면 검출 번호와 조립 번호

### 전체 검출기의 `instance_index`

각 클래스 안에서 1부터 시작한다. 서로 다른 클래스의 ‘1번’은 다른 부품이다. 완전 적재·정상 검출 시 정렬은 다음과 같다.

- GPU: x 오름차순. 왼쪽 1, 오른쪽 2.
- VRM: y순으로 묶은 5개 행마다 x순. 위쪽 1–5, 아래쪽 6–10.
- Inductor: y순으로 묶은 2개 행마다 x순. 위쪽 1–2, 아래쪽 3–4.
- SMD: y순으로 묶은 5개 행마다 x순. 위쪽 1–5, 아래쪽 6–10.
- HBM: 먼저 x순으로 왼쪽 8개와 오른쪽 8개를 나누고, 각 묶음에서 y순 2개씩 행을 만든 뒤 행 안에서 x순. 왼쪽 세트 1–8, 오른쪽 세트 9–16.
- Power Module: 먼저 x순으로 왼쪽 4개와 오른쪽 4개를 나누고, 묶음 안에서 y순 2개씩 행을 만든 뒤 x순. 왼쪽 세트 1–4, 오른쪽 세트 5–8.

완전 적재 시의 HBM/PM 번호 배치는 다음과 같다. 실제 기준영상의 위→아래, 왼쪽→오른쪽 순서를 나타낸다.

```text
HBM (16개)                 Power Module (8개)
세트1       세트2           세트1       세트2
 1  2       9 10             1 2        5 6
 3  4      11 12             3 4        7 8
 5  6      13 14
 7  8      15 16
```

이 정렬은 검출 배열의 순서다. 부품이 빠지거나 부분 검출되면 묶음과 번호가 압축·변경될 수 있다. 화면 번호만으로 영구적인 물체 식별이나 소비 완료 여부를 판단하면 안 된다.

### 생산용 선택 후 `instance_index`

먼저 위 고정 구획으로 세트 1을 선택한다. HBM/PM은 선택된 부품을 y순 2개씩 묶고 행 안에서 x순으로 번호를 다시 준다. 나머지는 선택된 부품을 x순으로 정렬한다. 기존 번호는 `detector_instance_index`에 남기고, 새 번호는 `instance_index=1..N`, `assembly_set_index=1`로 기록한다. 기존 `id`는 보존한다.

선택 부품 수가 부족하면 다른 세트를 가져와 보충하지 않는다. `TrayCaptureRetry`는 해당 클래스의 필요한 배치가 완전히 관측된 뒤 기준 셀을 설정하고 좌표로 대응시킨다. 따라서 부분 관측에서 임시로 압축된 번호만 믿고 조립하지 않는다.

| 조립 순서 | 선택한 클래스 | 로컬 번호 | 조립 슬롯 코드 |
|---:|---|---|---|
| 1 | gpu | 1 | GPU-01 |
| 2–9 | hbm | 1–8 | HBM-01…HBM-08 |
| 10–13 | long_orange | 1–4 | PM-01…PM-04 |
| 14–18 | black_block | 1–5 | VRM-01…VRM-05 |
| 19–20 | marked_white | 1–2 | IND-01…IND-02 |
| 21–25 | right_white_brown | 1–5 | CAP-01…CAP-05 |

위 슬롯 코드는 기판의 목표 위치 이름이며, 트레이 원본 픽셀 좌표나 클래스 전체 번호 자체가 아니다. 기준 코드의 `SLOT_SEQUENCE`와 `PART_TYPE` 대응을 기록한 것이고 실제 배치 성공을 나타내는 표는 아니다.

### 번호와 추적 ID 구분

| 필드 | 의미 |
|---|---|
| `instance_index` | 현재 검출 배열 또는 선택 세트 안의 번호. 어느 처리 단계인지 함께 봐야 함 |
| `detector_instance_index` | 세트 선택 직전 검출 번호를 보존한 값 |
| `calibration_instance_index` | 관측 소스 정보를 부여할 때의 원래 검출 번호 |
| `id` | 셀 추적 ID 또는 관측 단위 대체 ID. 세트 선택에서 보존 |
| `tray_registration_id` | 등록 단위 식별자 |
| `source_observation_id` | 어느 관측 프레임의 소스인지 구분하는 식별자 |
| `assembly_set_index` | 생산용 선택 세트 번호, 현재 1 |
| 슬롯 코드 | GPU-01 등의 조립 목적지/계획 이름 |

`TraySourceIdentity`는 같은 클래스의 기준영상 중심이 고정 앵커에서 12px 이내이고 일대일로 유일하게 대응하면 기존 ID를 유지한다. 앵커를 매 프레임 조금씩 옮기지 않으며 새 셀에는 UUID를 부여한다. 모호한 대응은 추측하지 않는다. 후속 `assign_observation_sources()`는 유효한 등록/관측·클래스/번호·고유 중심을 확인하고, 필요한 경우 관측 범위의 대체 ID를 만든다. 이 ID는 물체 일련번호나 실제 그리퍼 파지 증거가 아니다. 여기의 추적 반경 12px와 세트 경계 여유 12px는 수치가 같아도 서로 다른 조건이다.

## 7. 촬영 수용 조건 및 섹션 표시 조건

- 실시간 수량 50개 또는 화면 경계 표시만으로 조립 캡처가 통과한 것은 아니다.

- 이번 실시간 검증은 실제 `TrayCaptureRetry`를 사용했다. 관측 성숙도 기본 최소 20프레임과 부품별 품질 기준을 적용하고 연속 유효 4프레임을 확인했다. SMD 상세 품질은 근접 뷰에 위임하는 모드였다.
- 등록 상실이나 이미 수용한 좌표의 유의한 변동은 캐시 재사용을 제한한다. 전체 수량을 맞추기 위해 낮은 품질을 강제로 통과시키지 않는다.
- 섹션 노드의 TrayHome 판단은 최신 로봇 상태와 보정 자세를 비교한다. 기본 위치 허용값 0.8mm, 각도 0.15°, 상태 최대 나이 5초이며 ±180° 각도 래핑을 고려한다.
- `render_tray_live.py`는 로봇 이동 중 오버레이를 숨기고 TrayHome 여부에 따라 전체 트레이 표시와 근접 표시를 달리한다. `TRACKING`과 `at_trayhome`은 별개다.
