- 로봇 연결은 192.168.58.2, PC는 192.168.58.10, 인터페이스 enp3s0. 확인 시 유선 RX/TX 오류·드롭은 0.
- ping 30회 모두 응답, 손실 0%, 최대 왕복 0.248ms.
- 30초 TCP 상태 포트 20005 관측: 7446개 패킷, 최대 도착 간격 10.144ms, 캡처 커널 드롭 0.
- 독립 ROS 수신 공백 276.954ms 동안 TCP 패킷 70개가 PC에 도착했다. 이 재현에서는 PC 도착 이후 구간의 지연을 확인했다.
- 증거: runtime/feedback_link_diagnosis_20260911/summary.json, ros.json, packets.txt.

### 2차: 외부 ping 프로세스 대기 시간 추적

- 드라이버의 10ms 상태 타이머와 100ms ping 타이머가 기본 상호 배제 콜백 그룹을 공유하고, ping은 system()으로 종료를 기다리는 구조를 발견했다. 처음에는 이 구조를 원인 후보로 보았다.
- strace 계측에서 ping 자식 대기는 최대 19.845ms. ROS 공백 178.820/108.418/161.012ms 동안에도 TCP 패킷 44/28/40개가 도착했다. 관측 공백을 ping 대기로 설명할 근거는 없었다.
- 별도 TCP 공백 228.985ms가 관측됐으나 그동안 ROS 메시지는 22개 발행됐다. ROS 메시지 수신 자체만으로 SDK 내부 데이터의 최신 갱신을 증명할 수 없음을 확인했다.
- 추적 도구 자체의 부하 가능성이 있으며, 이 결과로 네트워크의 모든 순간 지연을 배제하지 않는다.
- 증거: runtime/feedback_ping_trace_20260911/summary.json, process.trace, ros.json, packets.txt.

### 3차: eBPF 함수 진입·종료 및 실제 API ROS take 계측

- 실행 중 드라이버 상태 콜백·ping·상태 발행 함수에 일시적 uprobe/uretprobe를 걸어 측정 후 해제했다.
- 상태 콜백 최대 2.806ms, 발행 함수 최대 2.569ms, ping 최대 6.298ms, 발행 간격 최대 17.048ms.
- 독립 ROS 수신기가 330.142ms 멈춘 동일 구간에 드라이버는 33회 발행했다. 이번 공백은 드라이버 발행 이후 구간에서 재현됐다.
- 실제 API 프로세스에서 관측한 성공한 rcl_take 간격은 최대 50.384ms. 이 관측은 Python 상태 콜백 완료 시각과 다르며, 실제 조립을 중단시킨 API의 250ms 공백은 이번 구간에서 재현되지 않았다.
- SDK 내부 패킷 갱신 시각은 직접 계측하지 않았다. 상태 콜백 소요 시간에는 SDK 상태 조회 호출이 포함된다.
- 증거: runtime/feedback_function_trace_20260911/summary.json, comparison.json, functions.log, api.log, ros.json, probe.bt, api.bt.

## 현재 결론과 다음 작업

- 확정: 일부 수신 공백은 TCP 수신 및 드라이버 발행이 정상적으로 이어지는 동안 PC 내부 ROS 수신 구간에서 발생했다.
- 미확정: 실제 조립 API 중단의 근본 원인이 DDS 전달, executor 스케줄링, Python 콜백/GIL, 시스템 부하 중 무엇인지. ping을 직접 원인으로 단정했던 추정은 계측 결과로 뒷받침되지 않았다.
- 통신 지연 문제를 수정 완료로 처리하지 않는다. 다음 진단은 실제 API의 상태 콜백 완료와 DDS 수신·실행 대기 시간을 같은 구간에서 기록해 실제 250ms 공백을 재현하는 것이다.
- 사용자는 재시도 의사를 밝혔고, 이미 배치된 GPU·HBM-01을 원래 트레이에 돌려놓고 빈 기판·빈 그리퍼를 확인한 후 복구·새 실행 ID로 시작하도록 안내했다. 이후 현장 정리·복구·새 Start의 실제 수행과 결과는 이 기록 시점에 확인하지 않았다.
- 로컬 코드 커밋: `2f3379a`(VRM 동기화·전체 재촬영), `52e0d57`(API 제거 검사 세트 선택 보존). 마지막 코드 회귀 검증은 870개 통과. 이후 통신 계측은 코드 수정이나 전체 조립 성공 검증이 아니다.
