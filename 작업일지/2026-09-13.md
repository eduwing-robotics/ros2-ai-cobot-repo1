# 2026-09-13 작업 기록

## 변경과 적용

1. 전체 부품 검출: 같은 영상의 다중 크기/180도 재검출, 기존 품질 기준 유지, 깊이·위치 변화 시 제한된 전체 트레이 재촬영. 생산용 1번 세트 선택은 표시용 전체 검출과 구분한다.
2. 그리퍼: 런처 시작 직후 활성 상태 확인/활성화. 실제 그리퍼 개폐나 팔 이동을 자동 시작하지 않는다.
3. 피드백: 같은 PC의 드라이버와 API 사이에 독립 Unix datagram 수신 경로 적용. v2 프레임에 연속 MoveJ 지원 비트를 포함하여 부품마다 수행하던 2초 DDS 기능 확인 요청을 제거했다. 250ms 신선도와 정지/오류 검증은 유지했다.
4. Unity 대응: 관측 내 유일한 ID를 표시·실행 양쪽에서 사용하고 원본 calibration_instance_index를 보존한다. 실행 시작 후 부품·슬롯 대응 변경을 차단하며 Place는 완료된 Pick의 계획을 사용한다. 부품 대응 유효성과 실제 파지 증명은 별도다.
5. 마지막 ID 누락 실행 49de7115-da42-4061-8cac-8e3828f555e5의 기록을 오프라인 검증했다. HBM-05, PM-01, PM-03의 누락 ID 3개를 유효한 원본 관측 정보로 처리했고 비-SMD 20개 대응이 통과했다. 원본 실행 기록은 수정하거나 재생하지 않았다.

## 검증과 한계

- 관련 수정 시 전체 테스트 1,020개 통과, 추가 모호한 관측 차단 후 어댑터 관련 31개 통과. GitHub 업로드 전 최종 검사 결과는 아래에 추가한다.
- 로컬 피드백 v2 실측: 120.03초, 상태 조회 2,338회, 최대 수신 간격 18.828ms, 최대 전달 지연 3.548ms. 실제 로봇 이동 없이 수행한 검증이다.
- 25개 각각의 Pick/Place와 25개 연속 조립/50개 요청 시뮬레이션에서 식별자 유지·거부 시 동작 차단을 검사했다.
- 사용자는 설비 시연 영상을 촬영했다고 알렸다. 이를 최신 변경 후 반복 조립 정확도나 슬롯 검사 PASS의 수치 증거로 대체하지 않는다.
- 새 ID 계약 적용 시 로봇은 SMD 촬영 위치였고 전체 트레이 라이브 토픽은 valid=false/0개였다. 실제 전체 트레이 재촬영 및 Unity 부착/배치 화면 검증은 후속 실기 확인 대상이다.
- 드라이버 발행 시각은 SDK 내부 원본 패킷 갱신의 완전한 증명이 아니다. 통신 단절이나 실제 설비 오류는 계속 안전 정지 대상이다.
