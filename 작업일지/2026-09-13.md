5. 마지막 ID 누락 실행 49de7115-da42-4061-8cac-8e3828f555e5의 기록을 오프라인 검증했다. HBM-05, PM-01, PM-03의 누락 ID 3개를 유효한 원본 관측 정보로 처리했고 비-SMD 20개 대응이 통과했다. 원본 실행 기록은 수정하거나 재생하지 않았다.

## 현장 문제 확인과 대응 기록

### 기존 실패 상태와 복구

- 9월 11일 실행 `a3665bf3-89b7-447c-af87-38f4c0d64b80`은 GPU/HBM/PM/VRM-01까지 14개 배치 동작 뒤 VRM-02 제거 검사에서 `picked cell still occupied`가 3회 발생하여 정지했다. 전체 조립 완료나 검사 PASS가 아니며 외부 실행기의 복구 잠금은 생산 DB의 과거 Job 삭제와 별개로 남아 있었다.
- 작업자의 현장 확인 후 그리퍼 활성화와 복구를 진행했다. 이후 발생한 실패는 새 실행별로 구분하여 확인했으며, 복구 상태를 수동으로 편집하거나 과거 실행 ID를 재사용하지 않았다.
- 재실행 안내 전 조회에서 `failed_recovered`, `recovery_required=false`, 실시간 `robot_motion_done=1`, `active_operation=null`, `robot_health_clear=true`를 확인한 시점에도 외부 기록의 `stop_verified=false`가 남아 있었다. 실시간 정지와 기록 불일치를 사용자에게 알렸으며 모든 복구 조건이 충족됐다고 단정하지 않았다. 이 값은 해당 조회 시점의 기록이다.

### 검출 실패와 피드백 지연을 구분

- 앞선 트레이 캡처에서는 VRM 계열 검출 신뢰도 부족과 약 2mm의 좌표 변화가 발생했다. 전 부품 재검출·전체 재촬영 경로를 보완했으며 신뢰도 기준을 낮춰 통과시키지 않았다.
- 실행 `4eee67a8-f3f5-4e8a-9b4b-bc0cab36be08`은 HBM-03 픽업 후 제거 검사에서 250ms 내 새 피드백을 받지 못해 정지했다. 당시 `latest_age_ms`는 약 254.5ms였다. 로컬 피드백 수신 경로를 구현하고 드라이버/API를 갱신했다.
- 그 뒤 실행 `ad2fb3e0-c317-45e0-8dd6-f3def01e80f8`은 GPU-01/HBM-01 배치 후 HBM-02를 집고 기판으로 이동하기 직전에 `continuous driver capability timeout`으로 정지했다. 이번에는 위치 피드백이 아니라 드라이버 기능 확인 요청의 2초 시간 초과였다. 로컬 피드백 v2에 기능 지원 정보를 포함하여 해당 DDS 왕복을 제거했다.
- 두 시간 초과는 서로 다른 경로다. 앞선 수정만으로 모든 지연이 해결됐다고 안내할 수 없음을 확인하고, 준비 조회·그리퍼·이동 명령·결과 대기 경로도 재점검했다. 응답이 불명확한 이동 명령의 자동 재전송은 추가하지 않았다.

### Unity 표시와 rqt 트레이 섹션

- ‘Unity에 1세트 캘리브레이션만 들어와 부품이 안 보였다’는 설명을 확인했다. 조회 시 `/vision/tray/unity_state`는 `valid=true`, 전체 50개를 전송했고 생산용 캡처만 선택 세트 25개를 사용했다. 당시 Unity가 실제 수신한 패킷/Console 로그는 없어 화면 누락 원인을 세트 수만으로 확정하지 않았다.
- 이후 명시적으로 요청받은 부품 ID 문제는 마지막 실행의 실제 기록에서 확인하고 위 소스 대응 계약으로 수정했다. 과거 source_id 누락 callback과 최신 수정 후 실제 화면 검증을 구분한다.
- rqt의 트레이 섹션 미표시를 처음 Unity 표시 문제로 잘못 이해했다가 바로잡았다. 실제 rqt는 `/vision/assembly/image`를 보고 있었고, 렌더러는 TrayHome에서 섹션을 표시한다.
- 확인 당시 플랜지 Z 약 506.997mm, TrayHome 기준 494.877mm로 약 12.12mm 차이였다. `at_trayhome=false`, 트레이 추적 자체는 `TRACKING`이었다. 높이/자세 조건 때문에 섹션이 숨겨진 것으로 확인했으며 표시 확인만을 위해 로봇을 이동시키지 않았다.

### 발표 구성과 근거

- 7장: 25개 부품 조립 실행 흐름, 45초.
- 8장: RGB-D/Hand-Eye로 Camera→Flange→Base 좌표 연결, 55초.
- 9장: 180도 방향 모호성과 손목 회전 경로, 55초. Euler 표기 경계·부품 대칭·관절 제약을 같은 문제로 뭉뚱그리지 않는다.
- 10장: 실물 조립 영상과 확인한 성과, 85초. 영상 포함 총 4분.
- 부록 후보: 검출/피드백 공통 안정화, 실물 부품과 DT를 연결하는 식별자.
- 전체 프로젝트 설명은 ‘모형 반도체 패키지의 조립·검사·결과 추적’으로 정리했다. 실제 반도체 제조/본딩 공정이나 무교시 자동화로 과장하지 않는다.
- 최신 검사 브랜치의 기본 `PROVISIONAL_BINARY_V1`은 임시 운영 PASS/FAIL이며 엄격한 `validated_decision`과 별도다. 검사 정확도 검증 완료라고 쓰지 않도록 반영했다.
- 9월 8일의 25개 동작 완료/22분55.7초는 당시 기록으로만 구분하고 최신 사이클 시간으로 사용하지 않는다. 1,021개 테스트도 물리 조립 횟수나 성공률이 아니다.
