## 안전 운용 기준과 확인 사항

- 실제 이동 전마다 Tool1/User0, AUTO 모드, 정지 상태, 비상정지·충돌·주요 경보, 관절 소프트 리밋과 IK를 확인.
- 수평 이동은 주로 30%, 비접촉 하강은 20%, 최종 파지 접근과 최초 상승은 10% 사용.
- 부품 근처에서 XY를 변경할 때는 먼저 수직 상승한 뒤 XY 이동, 이후 수직 재하강하는 순서를 사용.
- 로봇 자체 반복오차보다 TCP, 카메라-그리퍼 중심, 부품별 검출 중심 차이를 주요 시스템 오차로 판단.
- ROS 그리퍼 위치 피드백이 물리 상태와 일시적으로 불일치한 사례가 있어, 직접 조회와 육안 확인을 병행.

## 부품 배치 순서 저장

- 조립 순서: GPU → HBM → Power Module → VRM → Inductor → SMD.
- HBM: 왼쪽 세트 1~8 완료 후 오른쪽 세트 9~16, 각 세트는 4행×2열 row-major.
- Power Module: 왼쪽 세트 1~4 완료 후 오른쪽 세트 5~8, 각 세트는 2행×2열 row-major.
- VRM: 위쪽 세트 왼쪽부터 1~5, 아래쪽 세트 왼쪽부터 6~10.
- Inductor: 첫 줄 왼쪽부터 1,2, 다음 줄 3,4.
- SMD: 같은 row-major 방식.

## GitHub 방식 검토 및 마커리스 트레이 등록

- GitHub `vision-robot-conveyor-control` 브랜치의 방식이 ChArUco 평면 정합 + contour 중심 + hand-eye 변환임을 확인.
- 데모 외관상 ArUco를 사용하지 않기로 하고 기존 SIFT, 트레이 외곽선, Huber line fitting, homography 방식 활용.
- 30프레임 마커리스 코너 안정성 측정 결과 전체 RMS 약 0.327 px.
- 트레이 실측:
  - 위/아래 355 mm
  - 왼쪽 310 mm
  - 오른쪽 305 mm
  - 대각선 467/470 mm
- 트레이 형상 최소제곱 잔차 RMS 0.556 mm, 최대 0.674 mm로 ±0.5 mm 목표보다 약간 큼.
- GPU 기준점 세 개가 영상에서 거의 같은 높이에 놓여 전역 affine 보정용으로는 불충분함을 확인.
- 두 GPU 기준점 변환을 HBM 영역까지 외삽하면 기존 3D 결과와 약 166 mm 차이가 나 실제 이동을 차단.
- 트레이 평면 보정 상태는 계측 완료가 아닌 `OPERATOR_VISUALLY_VALIDATED`로 유지.

## Power Module 중심·각도·파지 시험

- Power Module 1번이 약 4.82° 기울어 있었으나 최초 접근에서 자세 정렬 옵션을 누락한 문제 확인.
- 이후 방향성 부품은 중심 검출 → 긴 축 검출 → `tool_y` 정렬 → 중심 보정 순으로 처리.
- Power Module 1번 기준:
  - 기준 Rz 85.185°
  - Base XY 전체 보정: X -2.309 mm, Y +0.665 mm
  - Tool XY 보정: X +0.469 mm, Y -2.357 mm
  - 화면 오른쪽 누적 미세 조정량 2.75 mm 포함
  - 열림 30, 닫힘 26
  - 검출 표면 Z -45.812 mm
  - 티칭 파지 TCP Z -50.550 mm
  - 파지 Z 오프셋 -4.738 mm
- Tool 보정 Y 부호를 처음 잘못 환산했으나 dry-run 출력에서 발견해 실제 이동 전에 차단하고 `+0.469, -2.357`로 수정.
- Power Module 2번:
  - 각도 자동 정렬 및 보정 적용 후 닫힘 26, 5 mm 상승 성공.
  - 사용자가 중심이 약간 어긋났다고 판단하여 완전 검증 처리하지 않음.
- Power Module 3번:
  - 각도 자동 정렬 및 동일 보정 적용.
  - 닫힘 26 후 5 mm 상승, 육안상 파지 성공.
  - 닫힘 직후 직접 위치 조회가 순간 0, 이후 ROS 상태는 26으로 정상 표시되어 반복 확인 필요.
- 두 부품 모두 다시 원래 위치에 내려놓고 그리퍼 30으로 해제.

## 실행 중 발견한 문제와 조치

- 카메라가 약 90° 회전한 상태에서 화면 방향과 Base 축을 혼동해 HBM을 Base -X 방향으로 이동한 실수 발생.
  - 화면 오른쪽은 기준 자세에서 Base +Y임을 재확인.
  - 잘못된 이동을 복구하고 이후 회전된 Tool 방향으로 화면 보정을 변환.
- 명시 좌표 모드에서는 `--approach-offset-mm`가 자동 적용되지 않으므로 목표 Z에 직접 오프셋을 합산해야 함.
- TrayHome 복귀 시 안전 여유 100 mm가 Z 437.88 mm를 생성했고 컨트롤러 오류 112로 거부.
  - 실제 이동은 발생하지 않음.
  - 현재 XY에서 Z 338 mm까지 먼저 상승한 뒤 안전 여유 50 mm, 최대 Z 387.88 mm로 복귀하는 방식은 성공.
- 부품 근처에서 사용자가 수동으로 Z를 변경한 경우 매번 실제 상태를 다시 읽고 기존 목표를 재사용하지 않음.
