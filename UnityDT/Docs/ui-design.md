# FR5 HMI 화면 설계 원칙

이 문서는 화면 구현 값이 아니라 FR5 HMI가 유지해야 할 시각·상호작용 원칙을 설명합니다.

## 정보 계층

사용자는 짧은 시간 안에 다음 순서로 화면을 읽을 수 있어야 합니다.

1. 현재 운전 모드와 연결 상태
2. 정상·주의·위험 여부
3. 진행 중인 작업과 근거
4. 지금 가능한 대표 행동

화면마다 대표 행동은 하나를 우선합니다. 동일한 무게의 버튼과 지표를 늘려 사용자의 결정을 숨기지 않습니다.

## 색의 역할

색은 장식이 아니라 상태 의미에만 사용합니다.

- 빨강: 즉시 조치가 필요한 위험과 실패
- 주황: 주의 또는 검토가 필요한 상태
- 강조색: 현재 선택과 진행 위치
- 무채색: 정상, 보조 정보와 데이터 부재

정상 상태를 강한 색으로 채우지 않습니다. 상태는 색만으로 구분하지 않고 문자, 형태 또는 아이콘을 함께 사용합니다.

## 디지털 트윈과 데이터

RUN 화면에서 3D 트윈은 로봇과 셀 동작을 이해하는 중심 표현입니다. 계기와 알림은 트윈을 가리지 않으면서 현재 동작의 의미를 보완합니다.

요청, 검사와 품질 화면에서는 비교와 근거가 중심이므로 3D 표현보다 구조화된 정보와 다음 행동을 우선합니다. 모든 화면에 같은 시각 요소를 반복하지 않습니다.

## 값의 맥락

값은 단독 숫자가 아니라 다음 맥락과 함께 보여줍니다.

- 단위와 정상 범위
- 목표값과 실제값
- 측정 시각과 데이터 신선도
- 표본 수와 집계 기간
- 필요할 때 최근 변화 방향

경로가 없는 값을 추정하거나 샘플 데이터를 실데이터처럼 표시하지 않습니다.

## 화면 안정성

진행 중에도 요소의 위치와 크기를 가능한 한 유지합니다. 정상 상태에서 불필요한 애니메이션을 사용하지 않고, 움직임은 진행이나 즉시 확인해야 할 변화에만 사용합니다.

정보가 없을 때는 빈 공간을 임의 값으로 채우지 않습니다. 무엇이 없고 어떻게 연결할 수 있는지 설명합니다.

## 수동 조작

수동 화면은 실제 자세와 목표 미리보기를 분리합니다. 명령 전에는 운전 모드, 좌표 기준, 속도 제한과 안전 조건을 확인할 수 있어야 합니다.

적용과 취소의 결과를 구분하고, 확인되지 않은 명령을 성공으로 표시하지 않습니다. UI 제어는 하드웨어 enable 장치와 E-Stop을 대신하지 않습니다.

## 접근성과 검증

- 본문과 상태 텍스트는 배경 변화와 관계없이 읽을 수 있는 대비를 유지합니다.
- 작은 색 차이만으로 상태를 구분하지 않습니다.
- 주요 조작 영역은 장갑과 터치 사용을 고려합니다.
- 오류 메시지는 원인과 다음 행동을 함께 제공합니다.
- 화면 변경은 대표 해상도와 밝고 어두운 Scene 배경에서 검증합니다.

세부 색상, 크기와 배치는 UI 자산이 소유합니다. 이 값이 바뀌더라도 위 의미와 우선순위는 유지합니다.
