# FR5 디지털 트윈 UI 요구사항

현재 프로젝트는 Unity에서 작업 셀과 Pick & Place 목표를 지정하고, MoveIt에서 경로를 계획·검증한 뒤, ROS/FR5 제어기가 실제 움직임을 실행하는 구조를 기준으로 한다.

## 필요한 버튼

| 기능 | 비고 |
|---|---|
| SHADOW 모드 | ROS `/joint_states`를 받아 Unity 로봇이 실기 자세를 따라간다. 현재 구현됨. |
| MANUAL 모드 | Unity 안에서 관절별 속도를 직접 조작한다. 현재 구현됨. 실기 명령과 명확히 구분해야 한다. |
| Pick 위치 지정 | 선택한 부품 또는 3D 지점에 Pick 목표 Pose를 생성한다. |
| Place 위치 지정 | 선택한 3D 지점에 Place 목표 Pose를 생성한다. |
| 목표 자세 편집 | 위치 XYZ와 회전 RPY를 수치 또는 3D 핸들로 수정한다. |
| 경로 계획 | Pick/Place 목표를 MoveIt에 보내 IK, 관절 제한, 충돌 여부와 경로를 계산한다. |
| 경로 미리보기 | 계획된 궤적을 Unity 로봇의 고스트 또는 애니메이션으로 재생한다. |
| 실행 | 검증된 계획만 ROS/FR5 제어기에 전달한다. 실기 모드에서는 확인 절차가 필요하다. |
| 일시정지·재개 | 실행 중인 작업을 안전하게 일시정지하거나 재개한다. 제어기 지원 방식에 맞춰야 한다. |
| 작업 취소 | 현재 계획 또는 실행 요청을 취소한다. |
| 전체 정지 | 모든 Unity 관절 입력을 정지한다. 현재 구현됨. 물리 비상정지 장치를 대체하지 않는다. |
| 원점·대기 자세 이동 | 정의된 Home 또는 Safe Pose로 이동 계획을 요청한다. |
| 그리퍼 열기·닫기 | 현재는 Unity 그리퍼 시각 모델만 조작한다. 향후 실기 명령 및 상태 피드백 연결이 필요하다. |
| 카메라 전환 | Robot View와 Global View를 전환한다. 현재 구현됨. |
| 알람 확인·해제 | 원인을 확인한 뒤 해제 가능한 경고만 초기화한다. |

## 시각적으로 보여야 하는 기능

| 기능 | 비고 |
|---|---|
| 3D 작업 셀 | FR5, 그리퍼, 작업대, 부품, 장애물과 안전 영역을 한 화면에 표시한다. |
| 실기·시뮬레이션 모드 표시 | 실제 장비 제어 가능 여부를 색상과 문구로 항상 구분한다. |
| ROS 및 Watchdog 상태 | 연결, 스트리밍, 지연, 타임아웃 상태를 표시한다. 현재 기본 상태 표시가 구현됨. |
| MoveIt 상태 | 연결 여부와 계획 중·성공·실패·실행 중 상태를 표시한다. |
| 관절 상태 | J1~J6 각도와 속도, 관절 제한 접근 여부를 표시한다. 현재 기본 표시가 구현됨. |
| TCP 상태 | TCP의 위치 XYZ, 회전 RPY와 좌표축을 표시한다. |
| Pick·Place 마커 | Pick과 Place 목표를 서로 다른 색상과 방향 화살표로 표시한다. |
| 계획 경로 | TCP 경로 또는 로봇 고스트 자세로 계획 궤적을 표시한다. |
| 충돌 및 도달 가능성 | 충돌 객체는 빨간색, 도달 불가는 경고 아이콘과 이유를 표시한다. |
| 선택 부품 정보 | 부품 ID, 현재 Pose, 작업 상태와 충돌 객체 등록 여부를 표시한다. |
| 파지 상태 | 미파지, 파지 중, 파지 완료, 놓기 완료 상태를 표시한다. |
| 작업 진행 단계 | 대기, 접근, Pick, 이동, Place, 복귀 중 현재 단계를 강조한다. |
| 카메라 영상 | ROS 카메라 영상과 선택한 부품 또는 검출 결과를 함께 표시할 수 있어야 한다. |
| 이벤트·알람 로그 | 계획 실패, 통신 끊김, 충돌, 작업 완료 시각과 원인을 기록한다. |
| 좌표계와 단위 | `world`, `robot_base`, `tool`, `object` 좌표계 및 m/mm, deg/rad 단위를 명시한다. |

## 추가적으로 필요한 요소

| 기능 | 비고 |
|---|---|
| Unity↔ROS 좌표 변환 | Unity 좌표를 ROS TF 기준 Pose로 변환하고 축 방향과 단위를 일관되게 관리해야 한다. |
| 작업 셀 캘리브레이션 | Unity의 작업대·카메라·로봇·부품 위치를 실물 기준 좌표와 맞추는 절차가 필요하다. |
| MoveIt 요청 인터페이스 | 목표 Pose 전송, 계획 결과 수신, 실행·취소를 위한 ROS Action 또는 Service 연결이 필요하다. |
| Planning Scene 동기화 | Unity의 부품과 장애물을 MoveIt 충돌 객체로 등록·갱신해야 한다. |
| Attach·Detach 처리 | Pick 성공 시 부품을 그리퍼와 MoveIt 로봇에 부착하고 Place 후 분리해야 한다. |
| 작업 상태 머신 | `Idle → Plan → Preview → Execute → Complete/Failed` 흐름을 한 곳에서 관리해야 한다. |
| 실기 실행 인터록 | ROS 연결, Watchdog, 계획 성공, 충돌 없음, 사용자 승인 조건이 모두 만족될 때만 실행한다. |
| 실제 부품 위치 입력 | 실기 운용 시 Unity 수동 배치만 믿지 않고 카메라, 센서 또는 PLC 측정값으로 위치를 갱신한다. |
| 설정 저장 | Pick/Place Pose, Home Pose, 속도, 카메라와 작업 셀 설정을 저장하고 불러온다. |
| 조작 이력 | 누가 어떤 목표를 계획·실행·취소했는지 최소한의 기록을 남긴다. |

## 권장 화면 우선순위

| 기능 | 비고 |
|---|---|
| 1차 MVP | 3D 작업 셀, Pick/Place 지정, 경로 계획, 경로 미리보기, 실행, 상태·알람 표시까지 구현한다. |
| 2차 | 카메라 기반 부품 위치 갱신, Planning Scene 동기화, Attach/Detach와 작업 상태 머신을 연결한다. |
| 3차 | 생산 통계, 작업 기록 재생, 다중 부품·작업 관리와 권한 기능을 추가한다. |
