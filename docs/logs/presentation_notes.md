# 발표 자료 준비 기록

1. 산업 문제와 프로젝트 목표
2. 전체 제조 셀 구성과 세 카메라 역할
3. FR5 + PGEA-100-40 + D435 하드웨어 구성
4. Camera/Flange/TCP 좌표계 문제

9. 안전 설계와 한계
10. 데모 및 향후 개선

## 현재 발표에 사용할 수 있는 수치

- 기존 Hand-Eye 독립 검증 평균/최대: `1.833/2.981 mm`
- 동일 마커의 세 관측 자세 최대 차이: `2.923 mm`
- 안정 RGB 모드 측정 FPS: 약 `14.99 FPS`
- ChArUco 보드: DICT_5X5_50, 마커 17개, 코너 24개
- 고해상도 10자세 멀티포즈 검증: 프레임 jitter 최대 `0.053 mm`, Base XYZ
  전체 범위 `1.524/0.939/3.004 mm`, 3D RMS/최대 `1.218/2.172 mm`.
- 10자세 최적화 후보는 독립 검증 최대 오차가 `7~12 mm`로 악화되어 미적용.
  발표에서는 학습 데이터 적합보다 독립 검증을 우선한 사례로 설명한다.
- 정면 복귀 3회 최대 편차 `0.053 mm` 대 특정 기울기 편차 `2.417 mm`를
  원인 분리 실험의 핵심 비교 그래프로 사용한다.
- IPPE 대안은 기울기 자세 reprojection max 약 `3.6 px`로 악화되어 제외했다.
- 1920 독립 6자세 최대 오차: 공장 intrinsic `6.345 mm` → 해상도별 intrinsic
  `0.961 mm` → 새 Hand-Eye 포함 후보 `0.753 mm`.
- 물리 접근 반복 시험: 관측 자세 A `[-2.5,-2.5] mm`가 재방문 시 동일하게
  재현됐고 자세 B는 `[-5.5,0] mm`; 고정 TCP offset이 아닌 자세 의존 오차다.

## 반드시 구분해서 설명할 개념

- TCP와 Camera extrinsic은 서로 다름
- Flange pose와 TCP pose의 용도가 다름
- 카메라 기반 사람 감지는 물리적 비상정지를 대체하지 않음
- 현재 대상은 실제 반도체가 아니라 반도체 패키지형 모형임
## 2026-08-12 — 발표 핵심 근거: 독립 검증의 필요성

- 단순히 calibration RMS가 낮다고 실제 Robot Base 좌표가 정확한 것은 아니다.
- 화면 중앙뿐 아니라 가장자리·근거리·원거리 영상을 포함한 33장 데이터셋으로 카메라 모델의 일반화를 확보했다.
- Hand-Eye 후보는 별도의 6자세 데이터로 검증했으며, 평균/최대 Base 위치 오차를 기준으로 활성화 여부를 결정했다.
## 2026-08-12 — Hand-Eye 25자세 수집 결과

- 위치 변화 약 100 mm 이상, 손목 회전 각 축 양방향 ±12~14°를 포함해
  단순 평행 이동 중심 데이터의 퇴화 문제를 줄였다.
- 25자세 수집 후 OpenCV 방법별 독립 검증에서 ANDREFF/xyz가 최대 약
  1.28 mm로 가장 우수했지만, 학습 자세 내부 최대 편차 약 4.24 mm가 남아
  추가 검증 없이 자동 이동에 적용하지 않았다.
## 2026-08-12 — 데모 마일스톤: RGB-D Pick 성공

- 입력: 높이 10 mm 검정 테스트 물체
- 인식: RGB 물체 영역 + aligned depth + ChArUco 기준 평면
- 계획: 물체 위 100 mm 안전 접근, 근접 XY 보정, 단계 하강
- 실행: 바닥 1~2 mm 여유에서 저속 파지, 10 mm 시험 상승
- 결과: 물체 동반 상승 성공, 로봇/그리퍼/충돌 오류 없음
## 조립 대상 부품 구성

- 총 25개 자동 조립: GPU 1, HBM 8, 왼쪽 검정 블록 5, 우측 흰색+갈색
  5, 흰색+검정 표시 2, 긴 노랑/주황 부품 4.
- 기판의 작은 노란 소자는 일체 출력하며 자동 조립 수량에 포함하지 않는다.
- 반복 부품을 recipe 기반으로 처리하여 6개 비전·파지 설정으로 25개 공정을
  구성한다.

## CAD/Unity 데이터 활용 장면

- `ITEAM.prefab → 기판 중심 기준 mm 좌표 → board layout → FR5 target` 흐름을
  시스템 구성도에 넣는다.
- 전달 모델에서 요구 수량 25개 중 1개 누락을 자동 발견한 사례를 CAD 데이터
  검증 및 안전한 자동화의 필요성으로 설명한다.
- 시각 자료: `vision_assembly/config/board_layout_from_unity.svg`.

## TurtleBot 컨베이어 + S22 제어 설명

- 실물 영상과 컨베이어 모델링 사진을 나란히 제시하고, TurtleBot 구동륜을
  컨베이어 모터로 재사용했다는 점을 강조한다.
- 흐름 그림: `S22 기판 검출 → ROS 감속/정지 → board pose → FR5 조립 → S22
  검사`.
- stopper가 없어도 정지 후 실제 기판 pose를 다시 측정하므로 조립 좌표를 보정할
  수 있다는 것이 핵심 설계 포인트다.

## 팀 시스템 아키텍처 그림

- 하드웨어 구성도: `docs/architecture/hardware_architecture.svg`

## 2026-08-13 — AI/Vision 서버 데모 자료

- 소프트웨어 흐름은 `camera_manager → part_detector → assembly_inspector`의
  세 블록으로 설명한다.
- 실제 장비 없이도 동일 ROS 2 검사 인터페이스로 `25/25 PASS`와 HBM 1개 누락
  `24/25 FAIL`을 보여줄 수 있다.
- 발표에서는 “단순 YOLO 화면”이 아니라 `카메라 역할 분리 → 검출 → 공정 규칙
  판정 → Main Server 전달` 구조를 강조한다.
